# A 股交割单无后视复盘

只评价交易当时的决策质量，不用当天收盘、盘后最高最低、全天成交量、后续走势或之后的新闻来证明对错。

## 先收集证据

每笔交易至少需要：

- 代码或名称、买/卖、成交日期、成交时间、成交价、数量。
- 成交时点或之前的分时证据：当时的个股分时、所属行业表现、上证/深证/创业板状态。实时截图最佳。
- 交易计划或原始持仓成本（有则纳入；没有则明确只评价时点和执行）。

若只有收盘后的整日分时图，禁止根据成交点右侧的走势、当天收盘价、最高价、最低价评价。成交时截屏和可核验的历史分钟数据仍是首选；只有带买卖标记（B/S）的整日截图时，按下文「截图推断模式」评分，不要因缺少精确成交时间直接拒评。

## 读取交易前日线背景

使用本技能目录里的 `scripts/run_trade_context.sh` 读取 `r0-data`。安装目录可通过 `CLAUDE_PLUGIN_ROOT` 定位，脚本路径为 `${CLAUDE_PLUGIN_ROOT}/skills/trade-review/scripts/run_trade_context.sh`。脚本会强制过滤 `date >= 交易日` 的全部日K，即使本地仓已经有当天完整日K，也不会读取。

```bash
${CLAUDE_PLUGIN_ROOT}/skills/trade-review/scripts/run_trade_context.sh \
  --trade-date 2026-07-13 \
  --previous-session 2026-07-10 \
  --codes 603538,002156,600584 \
  --format json
```

逐只检查输出：

- `status=ready` 才能把日线趋势作为当时可见背景。
- `status=stale`、`missing`、`insufficient_history` 或 `freshness_unverified` 时，不把该股票的趋势判断说成可靠；先说明缺口。数据更新是长任务，未获用户同意不要自动运行 `r0-data update`。
- 记录脚本报告的 `data_cutoff`。交易日是 7 月 13 日时，合格背景只能截至前一个交易日；7 月 13 日的日K永远不参与本次评估。

脚本输出 5/20/60 日收益、均线位置、20/60 日区间位置、量能和换手变化、趋势状态。这些是背景，不是买卖信号本身。

## 检查成交前的公开消息

对每笔交易（至少对跳空、异常放量、单日大涨大跌的标的）检查成交时点前已公开的公司公告、业绩、行业政策等消息：联网搜索，或调用 stock-pulse。采信标准：

- 每条消息必须有可核验的公开时间戳，且严格早于成交时间；找不到发布时间的消息不作为“当时已知”。
- 当时已知的消息写进“当时已知背景”，参与解释走势和评分——例如跳空低开对应成交前的利空公告，卖出的失效证据就更强；找不到利空时，急跌更可能是情绪杀，结论要区分。
- 成交之后才公开的消息只能进事后教学段，不参与评分。

## 冻结成交时点的分时数据

`r0-data` 不含分钟K，不能单独判断买卖时点。拿到规范化成交记录和历史一分钟数据后，使用同一脚本运行：

```bash
${CLAUDE_PLUGIN_ROOT}/skills/trade-review/scripts/run_trade_context.sh \
  --trade-snapshot \
  --trades /path/to/trades.csv \
  --minute-bars /path/to/minute-bars.csv \
  --previous-session 2026-07-10 \
  --format json
```

其中 `trades.csv` 必含 `datetime,code,side,price,quantity,market_symbol`，可选 `sector_symbol`；`minute-bars.csv` 必含 `symbol,datetime,open,high,low,close,volume`，可选 `amount,prev_close`。一分钟K时间戳必须表示**该分钟已经结束**；脚本会丢弃成交所在分钟及其后的所有分钟，确保数据严格早于成交时刻。`market_symbol` 用于冻结当时大盘状态。

快照除价格结构外还输出三组证据，逐笔必须先看：

- `fill_time_check` 成交价时间窗核对：用全天分钟K反查成交价出现过的时间窗——只用于校正估算成交时间，不参与结构评价。`inconsistent` 说明估算时间不可信，以时间窗为准修正后重跑快照，并在复盘里注明修正。
- `sector_daily` 行业日线强度：复用插件 r1（申万一级行业），截至前一交易日、无后视。输出行业 5/20 日涨幅、热度 rank、是否动态主线、个股行业内位置和 R1 分。首次运行会联网刷新申万参考数据（约 1–2 分钟），跳过用 `--no-sector-daily`。缺少行业分时（`sector_symbol`）时，用它给「大盘和行业环境」评分并注明是日线级证据；连它也不可用，行业项才标证据不足。
- 量能：`intraday_volume_ratio`（截至成交前累计量 / 前 N 日同时段均值，即分时量比）和 `recent5m_volume_ratio`（最近 5 分钟量能相对当日此前均值）；用于判断分时触发的确认强度。

用户没有自备分钟数据、而成交日还在数据源保留窗口内（新浪一分钟K约保留最近 8 个交易日）时，先直接下载，不要跳过这条路：

```bash
${CLAUDE_PLUGIN_ROOT}/skills/trade-review/scripts/run_trade_context.sh \
  --fetch-minutes \
  --codes 002156,sz159530 \
  --date 2026-07-13 \
  --out /path/to/minute-bars.csv
```

- 数据源为新浪（akshare `stock_zh_a_minute`），未复权价，可与券商成交价直接比较；时间戳为分钟结束时刻，与 `--trade-snapshot` 口径一致。
- 默认附带 sh000001、sz399001、sz399006 三个大盘指数；ETF 和指数代码必须带 sh/sz 前缀，普通 6 位股票代码自动补前缀。
- 默认同时保留交易日前最多 5 个交易日的分钟K作量能基准（`--prior-days` 调整）；这些K全部早于交易日，不违反无后视。
- 新浪没有申万行业指数的分钟数据，行业项仍按证据不足处理。
- 脚本对某代码报“无数据”（超出保留窗口或停牌）时，该票回落到截图推断模式。

下载不到分钟数据时，若有带买卖标记的整日分时截图，按下文「截图推断模式」评分；截图也没有，才只输出日线背景并标记“时点证据不足”。

## 截图推断模式（只有整日截图时）

只有收盘后保存的整日分时截图、且图上有券商标注的买卖标记（B/S）时，把标记的横向位置当作成交时间的估算，照常走逐笔复盘，规则如下：

- 成交日的分钟数据若还能下载（见上节 `--fetch-minutes`），优先用估算时间跑 `--trade-snapshot` 冻结真实数据来替代读图；时间仍是估算，下述降档规则和置信度标注不变。
- 估算时间一律写成“约 HH:MM（图上位置估算）”，不写成精确成交时间。
- 只读标记左侧的图形：开盘结构、标记前价格与分时均价线的关系、标记前的量能分布、标记时相对早盘高低点的位置。标记右侧的一切走势、收盘价，以及出现在标记右侧的全日最高最低，全部禁用。
- 截图里没有当时的大盘或行业信息时，优先用 `sector_daily` 的行业日线强度评「大盘和行业环境」并注明是日线级证据；行业日线也不可用，该项才按证据不完整计、最高 1 分。
- 出现下列任一情况时，“分时触发”最高 1 分：标记落在开盘后 5 分钟内（左侧结构太短）；标记处于剧烈波动区，几分钟的估算误差就会改变结构判断；一个标记对应多笔汇总成交。
- 照常按四项给 0–8 分，但每笔结论必须标注“截图推断，置信度低”。

## 逐笔复盘方法

先写“当时已知什么”，再给结论。每笔按四项各 0–2 分评估，总分 0–8：

1. **大盘和行业环境**：当时市场风险偏好、行业是否同步走强/走弱。
2. **日线位置**：交易日前的趋势、支撑阻力、是否在延续或修复阶段。
3. **分时触发**：买入是否有确认，卖出是否有失效/减弱证据；只用成交时点以前的数据。
4. **风险与执行**：成交价相对当时均价/关键位、仓位、明确的失效位是否匹配。

买入重点找“趋势和分时同时确认”；卖出重点找“原有逻辑失效、相对强度转弱或风险暴露超过预设”。不要把后来涨跌当作对当时决定的评分依据。

每笔在四项评分之外，再给一行**趋势层结论**：用日线背景加行业日线强度给这只票定阶段（识别标准见 [references/review-rubric.md](references/review-rubric.md) 的趋势阶段口径），并检查操作方向与阶段是否匹配——延伸段顺势持有或兑现减仓、不做首次追高建仓；修复段只做轻仓试错且必须有失效位；高位滞涨段只减不加；下行段不接第一反弹。方向与阶段相反时，写明冲突并落到「优化」列。

## 事后教学（唯一允许后视的部分）

评分永远不用成交后的数据；但“下次怎样优化买卖点”天然需要全天量价。加 `--teaching` 重跑快照，逐笔输出全天最高/最低及出现时间、收盘相对成交价、全天VWAP、成交后最高/最低。用它提炼下次可执行的规则，例如“当天回踩当时均价企稳出现在 10:23，等回踩规则可低约 1% 进场”。教学内容必须：

- 与评分明确分开，标注“事后教学（含后视）”，绝不回流进四项评分；
- 写成下次可执行的触发条件（条件 → 动作），不写“当时应该怎样”的责备式结论。

## 输出格式

先给一句总体问题，再用表格逐笔输出：

| 标的/操作 | 当时已知背景 | 当时的结构判断 | 评分 | 保持 | 优化 |
|---|---|---|---:|---|---|

每一行必须写清：

- 日线数据截止日、时点证据等级（分钟数据 / 截图推断 / 证据不足）和精确或估算的成交时间；
- 支持这笔操作的证据，以及缺少或反对它的证据；
- “保持”列写这笔做对的、值得固化的动作（评分 ≥4 的笔必须给出；低分笔有局部做对的也要点名，没有就写“无”）；
- “优化”列写一个能执行的动作，例如“等重新站回当时均价再开仓”“跌破早盘低点即退出”“同一行业只保留一笔试仓”。

最后单列“组合层面”，包含四点：

- **当日市场定性**：用各笔冻结的大盘快照拼出当天风险偏好的走向（开盘→尾盘走强还是走弱），结合 `sector_daily` 说明当时的主线行业在哪；检查买入是否集中在非主线行业、或与当日风险方向相反。
- 是否在风险释放时净加仓、仓位是否集中、卖出释放的现金是否被无条件换入新票。
- 值得保持的动作清单（各配触发条件）。
- 需要优化的动作清单（各配触发条件）。

不要用收盘盈亏评价组合好坏。

详细的无后视边界和评分口径见 [references/review-rubric.md](references/review-rubric.md)。

## 例外与边界

- `r0-data` 只有日K，不能还原当日分钟走势；分钟级判断必须来自成交时截图、当时保存的分时数据、可核验的历史分钟数据，或截图推断模式下带买卖标记的整日截图（只读标记左侧）。
- 日线数据为后复权价格，适合判断趋势和区间位置；它不能与券商未复权成交价直接比较高低。
- 这是交易过程复盘，不构成未来买卖建议。
